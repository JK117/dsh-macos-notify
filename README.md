# dsh-macos-notify（macOS 会话通知）

DSH 需要你响应、或者一轮任务跑完时，在 macOS 通知中心弹一条系统通知。窗口在后台、最小化，或事件来自另一个会话时，你不会错过被阻塞的交互，也不会错过已经完成的任务；点击通知直接回到对应会话。

![icon](icon.svg)

## 会收到哪些通知

| 什么时候 | 通知标题 |
| --- | --- |
| 工具申请越权执行，等你允许 / 拒绝 | `DSH 等待你的授权` |
| 向你提问，等你作答 | `DSH 等待你的回答` |
| 计划模式提交方案，等你批准 | `DSH 等待你审批计划` |
| 其他待处理交互（未来新增） | `DSH 等待你的响应` |
| 一轮任务结束，会话空闲下来 | `DSH 会话已完成` |

正文是一行摘要，第二行是会话名，例如：

```text
DSH 等待你的授权
Bash：write outside workspace
会话：检查依赖
```

完成通知的正文是：

```text
DSH 会话已完成
本轮已结束，点击查看结果
会话：检查依赖
```

## 什么时候不会打扰你

- 窗口在前台，并且你正看着事件所属的会话——面板或结果已经在眼前，不弹。
- 请求处理完或被撤回后，通知自动收起，通知中心不留条目。
- 已经处理过的请求不会补弹通知。
- 一轮结束时如果还带着待处理的授权、提问或计划审批，只弹交互通知，不额外弹完成通知。
- 子会话跑完不弹；它所属的主会话还在继续，等主会话自己结束时再提醒。
- 同一会话再次开始运行时，上一条完成通知自动收起；连续多轮只保留最新一条完成通知。

窗口在后台、最小化，或事件来自别的会话时，才会提醒。

## 安装

1. 侧边栏「插件」页 → **Add plugin** → **Install a third-party plugin**，填入本目录的绝对路径。
2. 安装完成后**刷新窗口**——桌面端从 profile 软链读取 `client.js`，不刷新会继续用旧版。
3. 如果 macOS 询问是否允许「DeepSeek Harness」发送通知，选择允许；也可以在系统设置里随时检查。

## 使用

- **点击通知**：把 DSH 带到前台并切到对应会话；提问和计划审批还会重新打开作答面板。
- **处理请求**：通知自动消失。
- **完成通知**：点击回到会话查看结果；该会话开始下一轮时，上一条完成通知自动收起。
- **语言**：通知文案跟随 DSH 的语言设置（简体中文 / English）。
- **前提**：DSH 页面需要保持打开；页面关闭后既没有通知，也没有可作答的界面。

## 通知权限

| 使用方式 | 权限归属 | 找不到通知时检查 |
| --- | --- | --- |
| 桌面端 | DSH 桌面应用 | 系统设置 → 通知 → DeepSeek Harness |
| 浏览器访问 `dsh web` | 浏览器站点权限 | 浏览器站点设置 + 系统设置 → 通知 → 浏览器 |

权限被拒绝时插件静默工作，不影响 DSH 的交互流程本身。

## 卸载

插件页 **Remove**；或关闭插件开关，立即停止通知。

## 常见问题

| 现象 | 先查 |
| --- | --- |
| 完全没弹 | 是否刷新过窗口；通知权限；是否正看着事件所属的会话（按设计不弹） |
| 标题是「DSH 等待你的响应」 | 该交互没有专属文案，走通用兜底，属预期 |
| 完成后没弹 | 当时是否正看着该会话；结束瞬间是否带着待处理交互；是否是子会话；会话是否根本没进入运行状态 |
| 点击后没回到会话 | 会话可能已归档或删除 |
| 点击后没有作答面板 | 缺少 `ui-user-questions` 提供的能力 |
| 页面关闭后收不到通知 | 通知由页面发出，页面关闭时既没有通知也没有可作答的界面 |

## 开发与测试

无构建步骤，`client.js` 就是运行产物：

```bash
node --check client.js
node scripts/smoke-test.mjs
```

改完 `client.js` 后刷新窗口生效。调试开关、自动化断言与真机验收用例见产品文档。

发版时运行 `npm run release:check` 校验版本一致性，`npm run release:tag` 创建 tag。
